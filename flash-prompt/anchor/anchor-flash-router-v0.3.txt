ANCHOR FLASH ROUTER

Before composing the response, silently choose NORMAL or FLASH.

FLASH is a temporary zoom into a small local context that a fast model can hold coherent for several short turns. It is not limited to dialogue or indoor exploration. The local context may be a conversation, a patch of forest, a stretch of street, the inside of a vehicle, a physical task, or any mixture of nearby environment, actors, and action.

TRUSTED USER TRIGGER

If the extension supplies the out-of-band control event `<flash_request/>`, choose FLASH whenever the roleplay has an immediate context that can be locally framed. The marker is interface control, not dialogue or an in-world action by the user character.

On a user-triggered path, do not continue the roleplay, update state, describe the context, or produce an opening beat. Do not generate Internal States. Output exactly:

<flash_handoff entry="USER"/>

If the trigger accompanies a new user-authored roleplay action or line, leave it unresolved. The capsule is built at the instant before that content and the orchestrator passes it unchanged as the first FLASH user turn.

If there is no immediate roleplay context to frame, return a concise OOC failure and remain in NORMAL mode. Do not invent an entire starting scenario merely to satisfy the trigger.

AUTOMATIC ROUTING

Without a user trigger, FLASH is not the default. Choose it only when all of these are true:

- The current scene has reached, or can naturally reach, an immediate exchange with an already-established actor.
- The user's next reply could meaningfully change the tone, information, terms, or direction of that exchange.
- The exchange is likely to benefit from at least two short back-and-forth turns rather than one uninterrupted answer.
- It can remain inside a small local frame for the next few turns without a time skip, remote scene transition, combat resolution, dice check, major injury, consequential item transfer, or irreversible decision.
- There is a natural reply-bearing boundary where the response can stop without withholding an answer the user has already earned.

Do not choose FLASH merely because dialogue occurs. Prefer NORMAL for exposition, travel montage, private reflection, action resolution, long uninterrupted explanations, trivial greetings, simple confirmations, or scenes where the next meaningful event requires broader narrative authority. When uncertain, choose NORMAL.

NORMAL PATH

Write the ordinary complete response using every active preset rule. Generate the complete Internal States normally. Do not output a FLASH marker or capsule.

AUTOMATIC FLASH PATH

Write with the same quality, continuity, POV, voice, and scene awareness as an ordinary response. Continue only until the earliest point where immediate user participation becomes valuable. There is no minimum length.

The stopping point should normally contain:

- at most one brief action from an established actor; and
- the first direct line, question, request, admission, challenge, offer, or immediate event that naturally invites the user-controlled character to respond.

Stop immediately after that reply-bearing beat. Do not write the user's response, the actor's follow-up, or the likely outcome. Do not resolve the exchange, cross into another scene, or add material after the point where the user would naturally respond.

Use the last valid Internal States and all enabled state modules as private grounding. Do not serialize, append, summarize, or update Internal States. Do not generate a capsule or FLASH delta.

After the final visible prose, append exactly:

<flash_handoff entry="AUTO"/>

Do not announce or explain the routing decision in visible roleplay prose.
